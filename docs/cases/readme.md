由 AI agent 用 `html-semantics-auditor` skill 中定义的维度和流程对项目进行检查

问题维度解释：

**A — 文档结构与语言**
- [A1] `<html lang>` 存在且正确（zh-CN / en / en-US）— 声明页面主语言，搜索引擎据此本地化、屏幕阅读器据此选语音引擎
- [A2] `<head>` 含 `<meta charset>` 与 `<meta name=viewport>` — charset 防乱码，viewport 保证移动端正确缩放而非桌面尺寸缩小
- [A3] 每页有且仅有一个 `<main>` 地标 — 辅助技术可一键跳到正文主区，绕开重复导航
- [A4] 存在 skip-to-content 链接（跳转 `#main`）— 键盘用户每次进站都需 Tab 过整条导航，skip 链接让其直达正文
- [A5] `<title>` 非空、跨页唯一 — 标签页、搜索结果、书签都依赖它区分页面，空标题则多个标签页无法分辨
- [A6] 双语页面有 `<link rel=alternate hreflang>` 互相指向 — 告知搜索引擎不同语言版本的对应关系，向用户呈现本地化结果
- [A7] 外语片段用 `<span lang="en">` 标注 — 屏幕阅读器按片段切换发音语言，避免中英混读错乱

**B — 标题层级**
- [B1] 每页有且仅有一个 `<h1>` — 页面主旨的唯一入口，相当于书名；多 h1 会混淆大纲
- [B2] 标题层级不跳级（h1→h2 合法，h1→h3 禁）— 屏阅用户靠层级导航，跳级会丢失中间节点
- [B3] 不为样式用标题（如用 h3 只为加大字号）— 标题承载文档大纲语义，滥用会污染目录结构
- [B4] 标题文本非空、跨级不重复 — 空标题让大纲节点无意义，重复则无法分辨章节
- [B5] 标题不嵌套在非内容容器中作布局 — 标题应描述内容主题，不应沦为排版工具

**C — 语义化区块**
- [C1] 导航用 `<nav>`，非 `<div class="nav">` — 原生地标让屏阅可"跳过导航/直达导航"，div 则无此能力
- [C2] 页眉/页脚用 `<header>/<footer>`，非 div — 语义地标替代无意义 div，便于辅助技术与 SEO 识别区块
- [C3] 侧边栏/相关内容用 `<aside>` — 与主内容相关但非主干的部分（如相关链接、广告）单独标记
- [C4] 独立内容块用 `<article>` — 可独立分发/聚合的完整内容（博客文章、卡片、评论）
- [C5] 相关内容分组用 `<section>` + 标题 — 主题分节，需配标题才有意义；无标题则应改用 div
- [C6] 带说明的图片/图表用 `<figure>+<figcaption>` — 图与说明成组关联，便于引用和上下文理解
- [C7] 联系信息用 `<address>` — 语义化标记页面/文章作者联系方式，而非通用 div
- [C8] 时间用 `<time datetime>` — 机器可读时间戳，利于日历抓取、搜索和事件识别

**D — 文本级语义**
- [D1] 强调用 `<em>/<strong>`，非 `<i>/<b>`（除非纯样式无语义）— em/strong 带语义权重供屏阅改变语调，i/b 仅视觉样式
- [D2] 缩写用 `<abbr title>` — 鼠标悬停或屏阅可读出全称，避免缩写歧义
- [D3] 引用：行内 `<q>`，块级 `<blockquote cite>` — 语义化引用并标注来源 URL，利于追溯
- [D4] 作品标题用 `<cite>` — 标记书/影视/作品名，与普通斜体样式区分
- [D5] 代码用 `<code>`，预格式化 `<pre>` — 保留代码的等宽字体与缩进空白
- [D6] 高亮 `<mark>`，删除/插入 `<del>/<ins>` — 标记修改痕迹与重点，常用于 diff 展示
- [D7] 上下标 `<sup>/<sub>` — 化学式（H₂O）、数学（x²）、脚注等场景

**E — 列表语义**
- [E1] 无序 `<ul>`、有序 `<ol>`，不用 `<div>` 加 bullet — 屏阅可播报"列表，共 N 项"并逐项导航，div 加 bullet 则无法
- [E2] 术语-描述列表用 `<dl>/<dt>/<dd>` — 名词解释、键值对的语义化结构，比 table 更贴切
- [E3] 列表嵌套结构正确 — 子列表应嵌在 `<li>` 内，而非与 li 同级，否则层级关系错乱
- [E4] 不用 `<br>` 模拟列表项换行 — 用语义列表替代，辅助技术才能识别为列表

**F — 表格语义**
- [F1] 表格有 `<caption>` 或 `aria-label` — 屏阅用户先听标题再理解整张表的主旨
- [F2] `<th>` 带 `scope="col|row"` — 声明表头管辖的行/列，屏阅据此将表头与单元格关联播报
- [F3] 用 `<thead>/<tbody>/<tfoot>` 分组 — 语义化表头/正文/页脚，便于滚动锁定与样式控制
- [F4] 不用表格做布局（table layout）— 布局表格混淆语义、破坏响应式、屏阅线性朗读错乱
- [F5] 合并单元格用 `scope` 标注 — 复杂多级表头需显式声明对应关系，否则屏阅无法正确关联

**G — 图片与多媒体**
- [G1] `<img>` 必有 `alt`（内容图非空，装饰图 `alt=""`）— 屏阅据此描述图片；装饰图留空以跳过，避免干扰
- [G2] 不用图片做文字（img of text）— 文字图片无法缩放/选中/翻译，不可被搜索，且模糊时不可读
- [G3] 复杂图加文字描述（相邻段落或 `longdesc`）— 信息图/图表单靠 alt 难尽述，需补充详述
- [G4] `<video>/<audio>` 提供字幕 `<track>` — 听障用户与静音环境需要字幕或文字稿
- [G5] `<iframe>` 有 `title` — 屏阅据此告知用户嵌入内容主题，否则只读"框架"
- [G6] 图标按钮有 `aria-label` 或 `alt` — 纯图标无文字，需可访问名让屏阅读出"关闭/搜索"等动作

**H — 链接可访问性**
- [H1] `<a>` 有可访问名（文本/aria-label/aria-labelledby），禁空链接 — 空链接屏阅只读"链接"，用户不知去往何处
- [H2] 避免"点击这里/了解更多/here"等无上下文链接文本 — 脱离上下文（如屏阅的链接列表）时毫无信息量
- [H3] 外部链接 `target="_blank"` 配 `rel="noopener noreferrer"` — 防止新窗口通过 window.opera 操纵原窗口（安全与隐私风险）
- [H4] 链接到非 HTML 资源（PDF/下载）加视觉提示 — 让用户预期会打开新应用或下载，而非普通网页跳转
- [H5] 禁 `href="javascript:void(0)"`，用 `<button>` 替代 — `<a>` 语义是导航，触发脚本动作应使用按钮

**I — 表单语义**
- [I1] `<input>` 关联 `<label>`（for/id 或包裹）— label 可点击放大命中区，屏阅读出字段含义而非看不见的 placeholder
- [I2] 必填字段 `required` 或 `aria-required="true"` — 浏览器原生校验 + 屏阅播报"必填"
- [I3] `<button>` 显式 `type`（避免默认 submit 误触）— 表单内 button 默认 type=submit，可能引发意外提交
- [I4] 分组用 `<fieldset>/<legend>` — 相关字段（如"地址"组）成组并给组名，屏阅先读组名再读字段
- [I5] 错误提示 `aria-describedby` + `role="alert"` — 校验失败时即时通告屏阅用户，否则错误不可感知
- [I6] 占位符不替代 label — placeholder 输入后消失、对比度常不足、屏阅易忽略，不能承担字段名称职责

**J — 按钮与交互**
- [J1] 动作用 `<button>`，导航用 `<a>`，禁 `<div onclick>` — 按钮可键盘 Enter/Space 触发且屏阅可操作，div 不可达
- [J2] `<button>` 有可访问名 — 无文字按钮（如纯图标）需 aria-label 补充，否则屏阅只读"按钮"
- [J3] 禁 `tabindex>0`（避免乱序聚焦）— 仅用 0（可聚焦、自然顺序）或 -1（仅 JS 聚焦），正数会打乱 Tab 顺序
- [J4] 自定义交互组件补 ARIA role + keydown 处理 — 非原生组件（如自定义下拉）需补全 role、键盘操作、焦点管理
- [J5] 不冗余 ARIA（如 `<button role="button">`）— 原生已隐含的 role 再写一遍是无意义冗余，徒增噪音

**K — ARIA 与无障碍**
- [K1] 原生优先——能用原生语义就别加 ARIA — 原生元素自带键盘行为与语义，ARIA 是最后补丁手段
- [K2] `aria-hidden="true"` 用于装饰元素对屏阅隐藏 — 让屏阅跳过纯装饰图标/分隔符，减少噪音
- [K3] 视觉隐藏文本用 `.sr-only` 类，不用 `display:none`（屏阅不可见）— sr-only 视觉隐藏但屏阅仍可读，display:none 则全隐藏
- [K4] 动态内容用 `aria-live` 通告 — 异步更新（通知、错误、购物车数）让屏阅自动播报变化
- [K5] 信息不单靠颜色传递（另查对比度）— 色盲用户需有文字/图标/下划线等冗余线索，仅靠颜色会信息丢失
- [K6] 焦点可见——不全局 `outline:none` — 键盘用户依赖焦点轮廓定位当前元素，移除会使其"失明"

**L — 隐藏与 SSR/ClientOnly**
- [L1] `display:none` 屏阅不可见；`visibility:hidden` 仍占位不可见；`aria-hidden` 语义隐藏 — 三种隐藏方式效果不同：none 彻底移除、hidden 占位留白、aria-hidden 仅对辅助技术隐藏
- [L2] `<ClientOnly>`/`<client-only>` 内容仅客户端渲染，应有 fallback 降级占位 — 无 JS/SSR 阶段应有占位骨架，避免内容闪烁或空白
- [L3] `aria-hidden` 不应用于可聚焦元素（会误隐藏键盘焦点）— 会造成键盘用户焦点"消失"，应在可聚焦元素上移除而非隐藏
