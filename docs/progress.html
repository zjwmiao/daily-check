处理策略

  • 文档暂不生成 Description、Keywords
  • 文案类如TDK、Schema初稿由AI生成，Skill限制说明来源只能是页面内容，然后开发review+运营review
  • 确定性的逻辑需封装为脚本（查看脚本仓库）

检查标准（日常巡检workflow）

  • robots.txt：可访问、未全站禁止爬虫访问、声明 Sitemap 地址
  • sitemap：
    (1) sitemap地址本身可访问（从robots.txt取sitemap地址）
    (2) 随机抽取50个页面检查页面可访问
    (3) 随机抽取10个页面检查是否存在priority属性。
  • TDK/Schema：
    (1) 遍历sitemap条目，确保页面都有统一配置TDK/Schema（各社区项目跳过检查的路径匹配，在 projects-config.yaml 中配置）
    (2) 结合codegraph分析最近几次git commit检查是否有页面内容受影响，对受影响的页面做TDK/Schema的语义性检查：
    - TDK/Schema 内容是否与页面实际内容一致
    - 是否包含不存在于页面中的信息（如其他社区名称、无关关键词）
    - description 长度是否合理（建议 100-200 字符）
    - JSON-LD schema 类型是否合适
  • llms.txt/llms-full.txt：检查可访问性
  • SSR：body内容丰富、无Vue/Nuxt/React SPA空挂载点（从sitemap中抽10个页面检查）
